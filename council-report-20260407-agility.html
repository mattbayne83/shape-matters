Agility Model Review — April 7, 2026 • org-shape / Shape Matters
The Bug

The Agility pillar uses a damped harmonic oscillator (ζ = levels × DPL × √headcount / 2k). The physics are inverted: flat orgs score terribly, sluggish deep orgs score perfectly.

L=2, H=50, A=55 → ζ=0.02 → health=10 "Spinning Out" ← WRONG
L=2, H=200, A=55 → ζ=0.04 → health=11 ← WRONG
L=3, H=5K, A=20 → ζ=0.87 → health=96 "Dialed In" ← WRONG (low agility scores high)

Meanwhile, Pivot Speed (torque model) correctly scores flat orgs near 1.0
Council Verdict: Kill the Oscillator
Delete the damped harmonic oscillator. Promote Pivot Speed.
The oscillator's physics are directionally inverted — less mass should mean faster settling, but the formula says less mass = more oscillation. This is not a calibration problem. No clamp, feedback term, or extension can fix a model whose core assumption contradicts organizational reality.
The torque/fidelity model (Pivot Speed) already produces correct scores. Promote it to be the sole third-pillar metric. Rename the pillar to something concrete — "Responsiveness" or "Change Response."
Do not clamp ζ. Do not add correction terms. Do not expand to coupled oscillators. Delete the code.
The one thing to do first

Check whether Agility and Pivot Speed use the same input variables. If they do, no model will make them independent — the answer is definitively one pillar, not two. Run the correlation before writing any code.

Blind Spots Caught in Peer Review

1. Asymmetric health function needed. The Gaussian treats overdamped (slow but stable) and underdamped (chaotic) as equally bad. Organizationally, overdamped is far less dangerous. Any replacement must score asymmetrically.
2. No empirical validation. Nobody asked whether real org data supports any oscillator model. Model selection should follow data, not metaphor preference.
3. "Agility" is undefined for end users. If you can't explain it in one sentence to a VP, the model doesn't matter. Define the behavior before choosing the math.
4. Input independence. If the same inputs drive both Agility and Pivot Speed, no formula will make them independent. Two pillars measuring the same thing with different math is worse than one pillar measuring it correctly.
5. Graph-theoretic alternative. Shortest decision path through the org graph is simpler, more interpretable, and requires no physics metaphor at all.

Advisor Responses

The Contrarian — "Kill it. Curve-fitting to vibes."

You've encoded "more layers = more stable" as an axiom. The feedback loop patch at L=2 adds exactly 1.0 — conveniently pushing to critical damping. That's not modeling, it's hand-tuning.

Two metrics measuring the same thing with contradictory outputs isn't nuance — it's a credibility problem. If Agility needs to exist separately, redefine it as change-absorption capacity (queuing model).

The First Principles Thinker — "Wrong phenomenon entirely"

Organizational agility isn't about oscillation decay — it's about response fidelity to a step input. That's a control system problem, not a resonance problem.

Replace with closed-loop settling time: how long until the org is within 5% of the new target. This naturally rewards short feedback paths (flat orgs) and penalizes deep hierarchies.

The Expansionist — "Extend to coupled oscillator network"

The oscillator isn't broken, it's too small. Model the org as a coupled oscillator network with teams as nodes. Merge Agility + Pivot Speed into "Dynamic Response."

Peer review consensus: rejected. Complexity multiplies failure modes of an already-broken model. Over-engineering a broken metric.

The Outsider — "Metaphor is backwards" ★

Fewer people = less inertia = faster settling in reality. But the formula says fewer people = less damping = more oscillation. The analogy is inverted.

Flip the framing: model "how quickly does the org reach steady state." Response time = f(layers, handoffs) / adaptability. Small flat orgs settle fast. Bureaucracies settle slow. Math matches intuition without floors or bonuses.

Also: "Agility" and "Pivot Speed" sound like the same thing to anyone without your internal definitions.

The Executor — "Clamp and ship"

Add Math.max(0.5, ζ). One-line change. Doesn't alter deep org scores. Tests that break are validating the bug.

Peer review consensus: rejected. Clamping masks the inversion, destroys diagnostic resolution for all small orgs (everything 0.0–0.5 maps to the same score).
